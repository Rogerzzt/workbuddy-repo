## 通用前置（每次运行最先执行，严禁假设当前工作目录）
首行必须执行（顺序不可调换）：
```bash
export TZ=Asia/Shanghai
bash scripts/init_check.sh sunday
```
- `export TZ=Asia/Shanghai`：强制北京时间，消除机器本地时区漂移（update_watchlist.py 的 `date.today()` 依赖进程 TZ，必须在此环境下运行）。
- `bash scripts/init_check.sh sunday`：完成「目录锚定到项目根」+「周日速退」（非周日立即跳过并结束）。脚本内部已 `cd` 到项目根并校验 config/watchlist.json。
此后所有 data/ 、 config/ 、 scripts/ 相对路径均相对项目根解析（脚本已 cd 进去）。若需显式写绝对路径，统一用 "$WS/" 前缀。

## 容错总则（防静默无输出 · 强制）
本任务任何环节都不得因上游异常而整轮无产物。硬性规则：
1. 连接器失败必须降级而非中断：若某 MCP 连接器调用报错 / 返回不可用（含 neodata-financial-search 返回 "Tool not available"、token 过期），立即将该环节标记为「🔴数据缺失」，改用替代源继续，禁止 exit / 禁止整轮中止。
2. 替代源优先级（当 NeoData 不可用时）：① 腾讯自选股 data_sector 的概念 / 板块涨幅榜（已含热点题材信号）；② WebSearch 网络检索（和讯 / 腾讯财经 / 新浪财经等周末复盘与机构研判）。两者组合可覆盖「周末发酵题材」，无需 NeoData。
3. **WebSearch 网络检索四约束（Phase 3 · 2026-08-17 · 强制，防「小作文」污染选股）**：
   - **① 数值白名单提取**：WebSearch 结果**只允许提取数值型关键词片段**——申万一级行业周涨幅、板块主力净流入金额、机构席位龙虎榜净买入额、涨停家数、连板高度、政策文件具体条款等可量化信息，且**每条必须标注来源媒体与日期**（如「半导体设备周涨 4.2%（和讯·08-16）」）。观点性、叙事性文字（「有望爆发」「主力悄悄建仓」「下一个十倍股」类）一律不得摘抄进报告正文。
   - **② 禁止小作文直接支撑选股**：任何候选金股的入选理由中，网络检索结论**不得作为独立依据**；题材确认须**≥2 个独立来源交叉验证**（如 概念涨幅榜资金面 + 政策文件数值），仅单一网文提及的题材/个股不得进入步骤 2 候选池。
   - **③ 未验证定量数据标注**：WebSearch 检索到的定量数据若无法与 MCP 连接器（data_sector / data_fund_flow / data_lhb）交叉验证，一律在数值后标注「(网检·未验证)」，且不得用于主力行为档位判定（主力行为只认 MCP 资金数据与周K形态）。
   - **④ NeoData 固化尝试次数**：neodata-financial-search **尝试 1 次，失败即降级**（历史 3/3 全失败，实证不再浪费时间重试）——首次报错后直接走替代源优先级，不得二次重试。
4. 报告必须落盘：即使步骤 1~3 仅部分成功，仍须执行步骤 4~5 生成并保存报告，失败环节用 🔴数据缺失 明确标注，绝不允许「无输出」。
5. 腾讯文档上传工具可能未在本会话暴露：若 create_smartcanvas_by_mdx 不可用，直接降级步骤 5③（本地保存 + 说明），不要重试或卡死。

A 股周日热门板块挖掘与自选股动态调仓。所有数据必须真实采集，禁止编造数字或凭空捏造个股代码。本任务仅在周日运行（rrule 已限定 BYDAY=SU）。

核心目标：复盘本周资金与题材，挖掘下周看涨板块，从中提取 1~2 只龙头/人气股，并自动无缝更新到监控清单（watchlist.json）中，替代上一周的自动添加标的，形成"手动置顶固定、自动每周轮换"的隔离机制。

## ⛔ 硬性约束 · 自动轮换标的禁入板块（最高优先级，不可协商）
本任务自动挑选的「动态金股」（写入 watchlist 时 source=auto）**禁止选入创业板标的**：代码以 **300 / 301** 开头的一律不得入选，无论其涨幅、资金流入、龙虎榜或题材热度多突出，一律换下一只。
- **允许范围**：沪市主板 600 / 601 / 603 / 605，深市主板 000 / 001 / 002 / 003。
- **只约束自动标的**：用户手动置顶（source=manual）的标的不受此限，即便是创业板也必须原样保留，严禁以本约束为由剔除任何 manual 标的。
- **前置执行**：步骤 2 筛选时就要主动过滤掉 300/301 开头的代码，不要等到步骤 3 被脚本拦下再返工。
- **兜底门禁**：scripts/update_watchlist.py 内置同名黑名单（BLOCKED_BOARDS），一旦 picks 中出现创业板代码，脚本以 exit 2 终止且**不会写入任何内容**（watchlist 保持原样）。此时必须回到步骤 2 重新挑选非创业板标的后再次执行步骤 3；**严禁修改/绕过脚本门禁，严禁跳过步骤 3，严禁手工改写 watchlist.json**。
- 若过滤后该板块内已无合格标的，允许只选 1 只，或退回步骤 1 换板块；实在无合格标的则写入空数组 []（仅剥离上周 auto），并在报告中说明原因。

## 主力行为判定框架（本周维度 · 盘口语言·量价行为学 周频适配 · Phase 4 Flow Ratio 升级）
> 揭示主力资金**本周（刚结束交易周）**意图，在「本周主力净流入方向 + 周量能位置 + 价格周位置 + 周K线形态」基础上判定，
> 与「手动置顶」/「本周动态」等清单角色标记相互独立，也与涨跌颜色（🔴涨/🟢跌）相互独立。

**⚠️ 周频 Flow Ratio 前置硬门槛（Phase 4 · 附录 F 周频适配 · 先于一切主力档位判定，强制）**：对候选金股与剔除 auto 标的，必须先计算 **周 Flow Ratio = 本周主力净流入（data_fund_flow 近 5 日累计，元）÷ 本周总成交额（近 5 日成交额合计，元；data_quote/data_kline 日成交额累加）**。判定规则：
- **|周 Flow Ratio| < 2% → ⚪ 主力中性**（资金量级太小，属散户博弈/随机噪音，**禁止强行解读为主力建仓/加仓/减仓**，不得进入相应叙事与入选理由）；
- **周 Flow Ratio ≥ +2%** 且价格站上并依托周均线（周收盘 > 周VWAP/周MA）→ 🟣主力建仓（低位）或 🟣主力加仓（突破位）；周 Flow Ratio ≥ +2% 但周收盘弱于周均线 → 🟣主力诱多（对倒/被动承接嫌疑，谨慎）；
- **周 Flow Ratio ≤ −2%** 且周收盘 < 周均线 → 🟣主力减仓；周 Flow Ratio ≤ −2% 但周收盘 ≥ 周均线 → 🟣主力洗盘（震而不破）；
- 周成交额或周主力净额取不到 → 标注「数据缺失」，**禁止用无门槛的净流入正负臆造档位**；若工具仅支持单日数据，不得用单日净额除以周成交额凑数，直接按单日视角标注并降级置信度。
报告「主力行为(本周)」结论必须附周 Flow Ratio 数值（如 `🟣主力加仓（周 Flow Ratio +2.6%）`）。判定表见 `docs/report_format_spec.md` **附录 F**。**emoji 铁律：主力行为一律 🟣/⚪，严禁 🔴/🟢。**

**周频可取数据**：周K线形态（data_kline period=week，看长上/下影、量价配合）、本周主力净流入（fund_flow 近5日累计，或 data_fund_flow 周聚合）、周成交额（日成交额 5 日累加）、内外盘（data_quote，本周外盘>内盘=主动买盘占优）、周量能位置（周 vol_ratio）、龙虎榜（data_lhb，本周累计上榜看机构/游资净买卖）。

**核心判定基准（周频特征对比 · 盘口破译逐条对照此表）**：
| 周频指标 | 🟣主力建仓(本周) | 🟣主力加仓(本周) | 🟣主力减仓(本周·派发) | 🟣主力洗盘(本周) |
| --- | --- | --- | --- | --- |
| 周K线形态 | 低位承接、常带长下影，周量比≥1.0温和放量 | 周线流畅上扬、量价齐升，连续多周净流入 | 高位长上影滞涨派发，或周放量下跌；内盘>外盘 | 剧烈震荡、长上/下影但收重心不破关键支撑，周量放大价未深跌 |
| 成交量配合 | 周量比≥1.0，温和放量承接 | 量价齐升，持续放大 | 周放量下跌或天量滞涨 | 周量放大而价格未深跌 |
| 盘口/资金 | 本周主力净流入>0 居前，外盘≥内盘 | 净流入>0 且较上周递增（连续净流入） | 净流出<0 居前列，内盘>外盘 | 净流入有限波动，非持续撤离 |
| 周尾/收官 | 周五尾盘打压做低 | 周五抢筹/周线收强 | 周五偷拉造势掩护 | 守住关键支撑收盘 |

**本周评估 3 个关键维度（盘口破译必用）**：
1. 周均价线（周VWAP/周MA）支撑/阻力：股价站上并依托周均线=强势承接；受制于周均线下方=派发。
2. 本周内外盘与主力净额：外盘>内盘+超大单净流入=建仓/加仓；内盘>外盘+净流出=减仓。
3. 周空间位置：低位区放量承接=建仓；突破周线关键阻力=加仓；主升浪末端巨量宽震=减仓。

**辅助验证工具**：Level-2 周累计十档/千档盘口看"大单净流入/流出"；本周龙虎榜（若上榜）看机构席位与知名游资净买卖，为周度盘口观察提供交叉验证。

**6 档速判（Phase 4 · 周频 Flow Ratio 口径对应）**：
- 🟣主力建仓（本周）：周 Flow Ratio ≥ +2% 且低位承接形态，主力新进吸筹。
- 🟣主力加仓（本周）：周 Flow Ratio ≥ +2% 且站上/依托周均线、量价齐升，主力在原有仓位上追加。
- 🟣主力减仓（本周·派发）：周 Flow Ratio ≤ −2% 且周收盘弱于均线，主力离场。
- 🟣主力洗盘（本周）：周 Flow Ratio ≤ −2% 但周收盘守住均线/关键支撑，清洗浮筹、震而不破。
- 🟣主力诱多（本周）：周 Flow Ratio ≥ +2% 但周收盘明显弱于均线，对倒/被动承接嫌疑，谨慎。
- ⚪主力中性（本周）：|周 Flow Ratio| < 2%、净流入≈0、量能平稳、内外盘均衡 → 不标特殊档位。

**盘口破译四步（每周对候选金股/剔除 auto 标的必做）**：
1. 🔍核心结论：一句话判定本周主力动作，并**改用「判据吻合度」格式**：`**置信度：高 (3/3 判据共振)**`（或 `中 (2/3)` / `低 (1/3)`），紧跟具体判据清单（如 `周K低位长下影 + 周量比1.5温和放量 + 龙虎榜机构净买1.2亿`）。**严禁输出"建仓65%""概率75%"类伪概率**。模板见 `docs/report_format_spec.md` 附录 C。
2. 🔎盘口破译：用上表"核心判定基准"与"3 关键维度"，结合周K形态+周Flow Ratio+本周资金流+内外盘+量能逐条举证，标注来源；缺数据写「数据缺失」。
3. ⚠️虚假信号排查：识别"周线长上影无量=诱多""高位放量滞涨=派发""缩量假突破"等骗线，给"真实/诱多/诱空"判定。
4. 💡应对策略：基于动作给下周操作建议（持有/低吸/减仓/止损），与题材看涨逻辑并列；冲突时提示"主力与题材背离，谨慎"。

标记写入「监控清单调仓确认」表的「主力行为(本周)」列（🟣建仓/🟣加仓/🟣减仓/🟣洗盘/🟣诱多/⚪中性，附周 Flow Ratio 数值），并可在「金股挖掘」行首与题材逻辑并列（如「🟣主力建仓 + 题材共振」）。禁止使用 HTML `&lt;span&gt;` 颜色标签。

## 报告排版规范（行政研报级 · 强制）

报告必须严格遵循 `docs/report_format_spec.md`（唯一排版事实源，含 5 条强制规则与 5 份标准模板）。核心速记：

1. **首部摘要块**：报告首部用 `>` 块引用，至少三行——`生成时间（北京时间）` / 关键结论或验证结论 / `图例规范`（操作方向纯文字、🔴🟢仅表价格）。
2. **层级结构**：一级结论用 `>`；分节用 `## 📊 一、xxx` 形式的 emoji 序号标题；多标的多字段对比一律用**表格**，单标的纵向展开用分级列表（2 空格缩进嵌套）。

4. **北京时间戳**：所有时间标注 `(北京时间)`。
5. **零裸 HTML（12977 防御核心）**：禁止输出 `<div>/<span>/<br>/<style>/<font>/<img>` 及任何内联颜色或锁形图标；emoji 仅用 Unicode。上统一 `create_smartcanvas_by_mdx` + `content_format=markdown`，标题纯连字符/ASCII、**禁用全角括号**。
6. **Phase 2 增强（D1a/D1b/D3c）**：量能分位/情绪用文本进度条（Unicode 方块字符 `█▓░▒`，**普通文本、严禁代码围栏/行内反引号包裹**）；宽表瘦表 + 标的间 `---` 卡片分隔；金股研判核心结论用 **判据吻合度** 替代伪概率（见 `docs/report_format_spec.md` 附录 C）。
7. **Phase 3 增强（2026-08-17）**：WebSearch 网络检索受「四约束」管制（数值白名单提取、≥2 独立来源方可确认题材、未验证定量数据标注「(网检·未验证)」、NeoData 1 次失败即降级），详见容错总则第 2~3 条；主力行为档位判定只认 MCP 资金数据与周K形态，不认网络检索文字。
8. **Phase 4 增强（2026-08-17 晚 · 附录 F 周频适配）**：主力行为档位判定前置**周频 Flow Ratio ±2% 硬门槛**（本周主力净额/本周成交额；<2% 一律 ⚪中性）；档位结论必须附周 Flow Ratio 数值。

报告文件标题统一为「<本任务名>-YYYYMMDD」（如 `周日热门调仓-20260816.md`）；上传腾讯文档标题同此纯文件名风格。

## 步骤 0：周日确认（已由通用前置 init_check.sh sunday 完成）
周几速退已在通用前置阶段由 `bash scripts/init_check.sh sunday` 处理（非周日直接结束），且脚本已比对本地交易日历 `config/trading_calendar_YYYY.txt` 拦截法定节假日；本步骤无需重复执行。若任务已继续执行到此，说明当前确为周日，直接进入步骤 1。

## 步骤 1：全周资金与热门板块扫描 (MCP 连接器)
- 腾讯自选股 data_sector：查询近 5 日主力资金净流入排名靠前的板块，以及近 5 日涨幅居前的板块。提取 3~5 个共振板块。
- 腾讯自选股 data_fund_flow：取步骤 1 选出板块内候选龙头个股 + 当前 watchlist 中 source=auto 标的（本周将被轮换剔除者）的**本周主力资金净流入**（主力净流入 = 超大单 + 大单，单位元）。优先取近 5 交易日累计净流入；若工具仅支持单日，取最新交易日并标注「单日视角」。记录超大单/大单分项与占成交额比例，供步骤 2 / 步骤 4 判定「主力建仓 / 加仓 / 减仓 / 洗盘 / 诱多」档位。
- 腾讯自选股 data_quote / data_kline（period=day）：取候选标的**近 5 日成交额并累加为周成交额**（周 Flow Ratio 分母；工具仅单日时逐日累加，缺日标注）。
- 腾讯自选股 data_kline（period=week）：对候选板块龙头 + 本周将被轮换剔除的 auto 标的拉取周K，识别长上/下影、量价配合与重心位置，供「主力行为(本周)」盘口破译（洗盘/派发形态判定）；日内明细不足时以周K形态为准。
- NeoData 金融搜索 (neodata-financial-search)：查询本周末发酵的题材，查询句："本周末 A股 重点发酵题材 研报看好 板块 政策利好"。**尝试 1 次，失败即降级（Phase 3 硬规则）**——立即改用「腾讯自选股 data_sector 概念涨幅榜 + WebSearch 网络检索（受四约束管制）」替代，并在报告「数据来源与验证」中标注「NeoData 不可用，题材面改用概念榜 + 网络检索」。
- 结合资金面（真金白银买入）与消息面（周末舆论发酵），选定 1~2 个**下周最具确定性的看涨板块**，并给出简短逻辑。**题材结论必须注明确证方式**：「双源确证（资金榜+政策数值）」或「单源(网检·未验证)，仅观察不入选」。

## 步骤 2：人气个股精选 (MCP 连接器)
针对步骤 1 选出的板块，寻找 1~2 只龙头或人气股作为本周的"动态金股"：
- **⓪ 先做板块过滤（一票否决）**：候选池中凡代码以 300 / 301 开头（创业板）者，直接剔除，不参与后续任何比较。
- 腾讯自选股 data_quote / data_lhb：查该板块内的个股表现，筛选条件优先考虑：① 本周五涨停或涨幅 > 5%；② 近期有机构/游资龙虎榜净买入；③ 换手率活跃（> 5%）。
- **④ 主力行为优先（本周维度 · 周 Flow Ratio 门槛后）**：在同板块候选中，优先选**周 Flow Ratio ≥ +2%**、呈 🟣主力建仓 / 🟣主力加仓 / 🟣主力洗盘（震而不破）的个股；|周 Flow Ratio| < 2% 的候选一律视为 ⚪中性，不得以「主力建仓/加仓」作为入选理由；若候选出现 🟣主力减仓（周 Flow Ratio ≤ −2% 且跌破周均线），除非题材确定性极强，否则换下一只。**主力行为档位只认 MCP 资金数据（data_fund_flow / data_lhb）与周K形态，网络检索文字不得参与档位判定**。
- 确认选出的标的代码（格式如 sh600036 / sz000001，对应 watchlist 的 exchange：SSE=沪 / SZSE=深）、名称，及其入选的核心理由（含主力行为档位 + 周 Flow Ratio 数值）。
- **落笔前自检一遍**：逐一核对所选代码前三位不属于 300 / 301，确认无误后才可进入步骤 3。

## 步骤 3：动态更新 watchlist.json (调用固化脚本，禁止内联生成代码)
当前目录存在 watchlist.json，标的分两类："source": "manual"（手动指定、固定不变）与 "source": "auto"（机器自动挑选、每周一换）；结构为 {"etfs":[...], "stocks":[...]}，每项含 code / name / exchange / source。

⚠️ 关键约束：本步骤**禁止**在终端现场编写/粘贴 Python 代码。所有合并、剥离、兼容清洗与容错逻辑已固化为 scripts/update_watchlist.py（纳入版本控制、可独立测试），你必须直接调用它，而不是自己实现等价逻辑。

操作：
1. 把你（步骤 2）选出的 1~2 只金股写成**纯 JSON 数组**，保存到 data/watch_picks.json。
   元素只需三个字段（exchange：SSE=沪 / SZSE=深；source 与 type 由脚本自动补，无需手写）：
   ```json
   [
     {"code": "603986", "name": "兆易创新", "exchange": "SSE"},
     {"code": "002230", "name": "科大讯飞", "exchange": "SZSE"}
   ]
   ```
   若本周未选出任何标的，写入空数组 []（脚本将只剥离上周 auto、保留 manual，不做新增）。

2. 调用固化脚本执行合并（cwds 已为项目根，使用相对路径；用项目默认 python3）：
   ```bash
   TZ=Asia/Shanghai python3 scripts/update_watchlist.py --picks data/watch_picks.json --watchlist config/watchlist.json
   ```
   脚本会自动完成：① 兼容清洗旧数据补 manual；② 剥离上周 auto 仅留 manual；③ 把本周金股（自动打 source=auto）追加到 stocks 段末尾；④ 写回并保留 version/updated/description。运行成功会打印「Watchlist 更新成功！ETF: 手动N；个股: 手动M+自动K」。

3. **若脚本以 exit 2 报「板块硬门禁拦截」**：说明步骤 2 漏筛了创业板标的。此时 watchlist 未被修改，回到步骤 2 重选非创业板标的、覆盖写 data/watch_picks.json，再重新执行本步骤第 2 条。
   **防死循环熔断（硬规则）**：连续触发创业板拦截达到 **2 次** 后，禁止继续在原板块内反复重试，必须①**强制将选股范围扩大至沪深主板的次级相关板块**（如原选半导体设备→改选半导体材料/封测等主板标的，或改选同逻辑的其他主板题材）重试一次；②若扩大范围后仍无合格标的，**直接写入空数组 [] 执行一次**（仅剥离上周 auto，保留 manual），并在报告中明确标注「本周未选出合格标的（连续 2 次创业板拦截，已扩大范围仍无果）」。**无论如何绝不允许卡死在步骤 3**——流程必须向下推进到步骤 4 产出报告。

4. 读取更新后的 watchlist.json 校验：手动标的均保留（source=manual），本周新标的已挂载在 stocks 末尾（source=auto），且 etfs/stocks 均为合法数组。

## 步骤 4：生成报告
排版须严格遵循 `docs/report_format_spec.md`（行政研报级）：首部 `>` 摘要块、emoji 序号分节（如 `## 🔄 一、监控清单调仓确认`）、表格优先。
浅色主题 Markdown。**无论步骤 1~3 是否全部成功，本步骤都必须执行并产出报告；任一环节缺失数据用 🔴数据缺失 标注，不得整轮无产物。** 包含：

> **Phase 2 渲染增强（D1a/D1b）**：① 量能分位/情绪得分用**文本进度条**（Unicode 方块字符 `█▓░▒`，普通文本，**严禁代码围栏/行内反引号包裹**）；② 宽表瘦表 + 标的间 `---` 卡片分隔（`### 标的名` 起头，冗长盘口破译剥离到卡片）。详见 `docs/report_format_spec.md` 一.5 与 三。
### 一、 本周资金与周末发酵题材
列出 data_sector 与 NeoData（或替代源）查到的资金流入排行与周末热点。**网络检索信息只呈现数值型片段并逐条标注来源媒体与日期；无法交叉验证的定量数据标注「(网检·未验证)」；叙事性观点文字不得摘抄**。
### 二、 下周看涨板块与金股挖掘
详细说明为什么选中该板块，以及这 1~2 只个股的量价形态、龙虎榜资金逻辑；并补充**主力行为（本周）研判**：对每只候选金股按「盘口破译四步」给出 🔍核心结论（**判据吻合度**格式，禁用伪概率%）+🔎盘口破译（周K形态+周 Flow Ratio+本周资金流+内外盘举证）+⚠️虚假信号排查+💡应对策略，标注 🟣主力建仓 / 🟣主力加仓 / 🟣主力减仓 / 🟣主力洗盘 / 🟣主力诱多 / ⚪主力中性（均附周 Flow Ratio 数值），作为看涨确信度的支撑证据。若主力行为为 🟣主力减仓 / 🟣主力诱多 却与题材看涨相矛盾，须显式提示「主力与题材背离，谨慎」。
### 三、 监控清单调仓确认
输出调仓日志：
- 剔除（上周）: [标的名称]
- 调入（本周）: [标的名称]
- 当前清单全览：以表格展示（以「手动置顶」「本周动态」文字标注清单角色），**表格须含「主力行为(本周)」列（附周 Flow Ratio 数值）**，对至少「调入金股 + 剔除的上周 auto 标的」标注 🟣主力建仓 / 🟣主力加仓 / 🟣主力减仓 / 🟣主力洗盘 / 🟣主力诱多 / ⚪主力中性；被剔除的 auto 若显示 🟣主力减仓，说明「主力离场，调出合理」；若显示 🟣主力洗盘且未破关键支撑，说明「震仓洗盘，可保留观察」。
### 四、 数据来源与验证
注明各环节数据源（MCP / 爬虫 / WebSearch）；WebSearch 提取的数值片段逐条列出来源与是否交叉验证通过；NeoData 若 1 次失败即降级，注明降级路径；周 Flow Ratio 的分子分母取值口径（累计/单日）须注明。
